## Context & Sessions

Claude Code has a context window — a fixed amount of space that holds your conversation history, file contents, command outputs, and system instructions. As you work, it fills up. Understanding and managing context is key to productive sessions.

#### What is the Context Window?

Everything Claude knows during a session lives in the context window:

* System prompt and tool definitions — fixed overhead from Claude Code's built-in instructions and configured MCP servers
* Your messages and Claude's responses
* Files Claude has read
* Command outputs (test results, build logs)
* CLAUDE.md instructions
* Skill content (loaded on demand)

When context fills up, Claude compacts automatically — older tool outputs are cleared first, then the conversation is summarized. Important details from early in the session can get lost.

---

##### Check Your Context

Use ```/context```  to see what's using space in your current session:

```
/context
```

This shows how much of the context window is used and what's taking up space. Use it when Claude starts forgetting things you mentioned earlier — it means context is getting full.

---

#### Context Management Commands

##### Command	          What it does

/context	        Show what's using space in the context window
/clear	          Reset context entirely — start fresh
/compact	        Summarize and compress context while keeping the task
/rewind	          Restore conversation and/or code to a previous checkpoint

**Key Rule:**
If you've corrected Claude more than twice on the same issue, run `/clear` and start fresh with a better prompt. A clean session with a good prompt beats a long session with accumulated corrections.

---

### Sessions

Each time you run claude, a new session starts with a fresh context window. Sessions are saved locally — you can resume them later.

##### What's NOT saved between sessions

* Conversation history (unless you resume)
* File contents Claude read
* Decisions Claude made

##### What IS persistent across sessions

* CLAUDE.md — loaded at the start of every session (covered in Module 2)
* Auto memory — learnings Claude saves automatically about your project
* Your code changes — files Claude edited stay changed on disk

##### Resuming Sessions

When a task spans multiple sittings, pick up where you left off:

```
claude --continue
```

This resumes the most recent session in the current directory with full history intact. To choose from a list of past sessions:
```
claude --resume
```

##### When to Start Fresh vs. Continue
**Situation	        Action**
Switching to a completely different task	        `/clear` or start a new session
Same task, context getting large	                `/compact`
Made a mistake, want to go back	                  `/rewind`
Taking a break, coming back later	                Exit, then `claude --continue`
Want to try a different approach from scratch	    `/clear` with a new, better prompt

---
##### Session Handoffs

When your context is nearly full, you can hand off to a fresh session instead of resuming a bloated one.

**The technique: ** Before ending a session, ask Claude to write a summary. Start a new session and paste that summary as the first message. Fresh context, full knowledge.

```Write a handoff note summarizing what we worked on, what files were changed, what decisions were made, and what remains to be done. Save it to HANDOFF.md.```


Then start a fresh session:

```
/clear
```

Resume with the handoff file:

```
@HANDOFF.md Continue from where we left off.
```

The `@` syntax injects the file directly into the prompt — Claude sees it immediately without needing to read it separately. A 200-token handoff note replaces thousands of tokens of accumulated conversation.

##### When to Use Handoffs
Most of the time, claude --continue is sufficient. Use handoffs only when your context is heavily used and Claude starts forgetting earlier instructions.

#### Running Claude Without a Session
You can run Claude non-interactively for quick questions or scripting. The -p (print) flag runs the query, prints the response, and exits — no session is started or saved.

```
claude -p "explain what this project does"
```

This is useful for CI pipelines, pre-commit hooks, or quick one-shot questions where you don't need a conversation.
