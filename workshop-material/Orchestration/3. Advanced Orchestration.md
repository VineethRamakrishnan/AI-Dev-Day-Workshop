For complex tasks that need many agents working together, Claude Code provides agent teams and dynamic workflows. These are more advanced features — this section explains the concepts and demonstrates what's possible.

Agent Teams
Agent teams coordinate multiple independent Claude sessions with shared tasks and peer-to-peer messaging. Each teammate has its own context window and can work in parallel.

How Agent Teams Differ from Subagents
Subagents	Agent Teams
Context	Share parent's session	Each has its own independent context
Communication	Report back to parent only	Can message each other
Lifecycle	Finish and return a summary	Keep running until idle
Use case	Delegate a single task	Coordinate parallel workstreams
When to Use Agent Teams
Implementing a feature + writing tests + reviewing — all simultaneously
Researching a problem from multiple angles in parallel
Debugging with competing hypotheses
How It Works
Ask Claude to start a team:

Start an agent team: one agent adds a product rating feature to the backend, another adds the rating UI to the frontend, and a third writes tests for both.

A lead agent spawns teammates who:

Share a task list
Work on separate worktrees (no file conflicts)
Can message each other for coordination
Report back when their task is complete
Try It: Research with Agent Teams
Start an agent team to research how to add authentication to our shopping cart: one teammate investigates JWT-based auth, another investigates session-based auth. Have them both report their findings with pros and cons.

Observe: Two research agents work in parallel, each in their own context. When they finish, findings are reported back to the lead agent which synthesizes them.

Dynamic Workflows
Dynamic workflows are the most powerful orchestration mechanism. Claude writes a JavaScript orchestration script that plans work, spawns subagents in parallel, collects results, and synthesizes output.

How Dynamic Workflows Differ
Subagents	Agent Teams	Dynamic Workflows
Who orchestrates	Claude, turn by turn	A lead agent	A script Claude writes
Scale	A few per turn	A handful of peers (2-5)	Dozens to hundreds
Context	Shares parent's session	Each has its own independent context	Each agent gets isolated context
Communication	Reports back to parent only	Teammates can message each other	No inter-agent communication
Simple rule: Need agents to talk to each other → Agent Teams. Need to process many things in parallel → Dynamic Workflows.

Built-In: /deep-research
/deep-research is a built-in dynamic workflow that researches a question across many web sources in parallel:

/deep-research What are the security best practices for serverless APIs on AWS?

It fans out searches across several angles, cross-checks sources, and returns a cited report.

Watch Progress
While a workflow runs, monitor it with:

/workflows

This shows each phase, agent count, token usage, and elapsed time.

Try It: Deep Research
Run a deep research workflow on a topic relevant to the shopping cart:

/deep-research What are the latest approaches to securing serverless applications on AWS Lambda including IAM, API Gateway authorizers, and runtime protections?

Long-Running Workflow
Deep research can take several minutes as it fans out across many sources. Once you understand how it works, you can cancel the workflow:

Run /workflows
Select the running workflow
Press x to stop it
Observe: Multiple research agents fan out, search different aspects of the topic, cross-reference findings, and produce a comprehensive report with citations. This demonstrates orchestration at scale — many agents coordinated by a script, not manual prompting.

Try It: Trigger a Custom Workflow
Ask Claude to write and execute a workflow for the shopping cart project:

ultracode: audit every route in backend/routes/ for missing input validation, inconsistent error responses, and missing docstrings. Produce a prioritized report.

Or simply ask in natural language:

Use a workflow to audit every route in backend/routes/ for missing input validation and produce a report.

Observe: Claude writes a JavaScript script, spawns subagents for each route file, collects findings, and produces a consolidated report.

Saving Workflows for Reuse
After a successful workflow run:

Run /workflows
Select the completed run
Press s to save
Choose project (.claude/workflows/) or personal (~/.claude/workflows/)
The saved workflow runs as /<name> in future sessions — repeatable automation.

---

### Key Takeaways

* Agent teams coordinate multiple independent sessions for parallel work
* Dynamic workflows orchestrate dozens/hundreds of subagents via scripts Claude writes
* /deep-research is the built-in workflow for cross-referenced research
* ultracode keyword triggers Claude to plan and execute workflows automatically
* Save successful workflows for reuse across sessions
