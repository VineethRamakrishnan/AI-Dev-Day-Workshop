## Build & Iterate

Now that you know how to explore and prompt effectively, let's use Claude Code to make real changes — plan, implement, verify, and deploy.

### Permissions & Approvals

When Claude Code wants to edit a file or run a command, it asks for your approval first. You'll see the proposed change and can:

```
Accept — approve that single action
Reject — skip it and tell Claude to try something else
Accept All — trust Claude for the rest of the session (no more prompts)
```

You can toggle permission modes with Shift+Tab:

Mode	          Behavior [TODO: Table]
Default	        Claude asks before writing files or running commands
Plan mode	      Claude only reads and proposes — no edits at all until you switch back
Accept All	    Claude acts autonomously without asking (use for trusted, well-scoped tasks)


Workshop Tip
For this workshop, "Accept All" mode is convenient since you're working in a sandboxed environment. In production, use the default mode for unfamiliar tasks.

#### Plan Mode
For changes you want to review before they touch disk, switch to plan mode.

#### Toggle plan mode: Press Shift+Tab

In plan mode, Claude reads files and proposes a plan but makes no edits until you approve.

### The Recommended Workflow
Explore (plan mode): Claude reads files, answers questions
Plan (plan mode): Ask Claude to create a detailed implementation plan
Implement (default mode): Switch out of plan mode, let Claude code
Commit: Ask Claude to commit

```
I want to add a discount code feature to the cart. What files need to change? Create a plan and save it to the docs folder.
```


After reviewing the plan, choose option 1 (Yes, auto-accept edits) to let Claude implement it:

```
implement the discount code feature from your plan. write tests and run them.
```

#### Verification

Claude performs better when it can check its own work. Give it something to verify against — in this workshop, we'll use tests.

```
Write tests for the cart service using pytest. Cover adding items, removing items, and calculating totals. Run the tests after writing them.
```

Claude will:

1. Write test cases
2. Run pytest to verify
3. If tests fail, loop back and fix the issue automatically

### Fixing Bugs

**Introduce a Bug First**
To demonstrate how Claude identifies and fixes bugs, manually introduce a bug in the code. For example, modify the discount calculation logic in cart_service.py — change the math operation, remove a case conversion, or alter the discount amount formula so it produces incorrect results.

Once the bug is in place, ask Claude to investigate:

```
Some tests are failing now. Can you run pytest, check the root cause, and fix it?
```

Refactoring Code
```
refactor the cart_service.py to separate the tax calculation into its own method. maintain the same behavior. run tests after.
```

Creating Commits
```
summarize the changes I've made, then create a git commit with a descriptive message
```

Deploying Changes

After making changes, ask Claude to deploy:
```
Deploy the changes to AWS
```

Open the Shopping Cart App URL (from the workshop outputs) to verify your changes in the browser.

**Bonus Exercises**
If you finish early, try these on your own:

1. Add a wishlist feature where users can save products for later
2. Ask Claude to review the codebase for security issues
3. Refactor the tax calculation into a configurable rate instead of hardcoded 8%


**Key Takeaways**
* Claude Code is agentic — it reads, plans, acts, and verifies autonomously
* Provide specific context: file references, constraints, verification criteria
* Use plan mode for changes you want to review before implementation
* Always give Claude a way to verify its work (tests, build, lint)
* Deploy through Claude to see your changes live after each iteration
